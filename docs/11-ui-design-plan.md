## 0. 从仓库读到的、UI 必须服从的事实

DeepSeek Harness（`dsh`）的口号是 **Everything is a Plugin**。运行时没有不可替换的内核：模型适配、工具注册、会话日志、Agent 循环本身都是 Cordis 插件。

### 0.1 用户真正在「订阅」什么

官方安装教程把分发和运行拆成两件不同的东西：

| 概念 | 官方定义 | 对应工坊对象 |
|---|---|---|
| **Plugin** | 导出 `name` / `inject` / `apply(ctx, config)`（或 class `Service`）的模块 | 物品（Item） |
| **Bundle** | npm 包，`package.json` 里声明 `dsh.bundle.patch`，带一份 `cordis.patch.yml` | **可一键安装的货品** |
| **Profile** | `$DSH_HOME/profiles/<name>`，`dsh.profile.bundles` 有序列表 | 用户当前「已订阅列表」 |
| **Patch** | 按 `id` 整行覆盖或插入的配置层 | 用户本地覆盖 / 高级设置 |
| **Seam** | Service Definition + Provider + Consumer 三件套 | 依赖图里的「能力族」 |
| **Collection / 合集** | 社区已在用的类型；一个 Bundle 可插入多行插件；可安装发布是不可变 lock | Steam 合集 |

一键安装的真实语义不是「下载 zip」，而是：

```
dsh plugin --profile <当前档案> add <bundle>
```

卸载是 `dsh plugin ... remove <bundle>`。  
Git 安装会跑 `prepare` 构建脚本，pnpm ≥10 还要用户显式 `allowBuilds`。  
**UI 可以把这一步做成一键，但不能假装它没有信任代价。**

云端网站不直接执行该命令。界面发出的是 Install Intent；本机 Companion 重新解析、确认并调用官方路径。未连接 Companion 时，整站仍可浏览，主按钮降级为「复制安装命令」。

### 0.2 插件不是一种东西

Cookbook 与 `packages/` 分组已经给出可展示的形态：

- 工具（`ctx.tools.register`）
- 钩子 / 策略（`tools/pre-execute` 等 waterfall）
- Web UI / Conversation Node（`dsh.client` + 会话节点渲染器）
- LLM 适配器（`ctx.llm`）
- MCP 桥（一服务器一插件）
- Skill / Memory / Compaction / Workflow / Command
- Subagent Provider / Sandbox Provider
- 协议驱动（ACP 等）
- 合集型 Bundle（一次插入多行）

社区目录（`awesome-dsh-plugins`）已在用的粗分类：Web UI 增强、Agent 能力、技能、基建、合集、社区。官方目前只有 GitHub topic，没有工坊。无 `dsh.bundle` 声明的库包默认可发现、不可一键安装。

### 0.3 依赖有三层，UI 不能合成一层

1. **运行时 `inject[]`**：等 `tools` / `llm` / `agents` 等 `ctx` 键就绪才加载
2. **Seam 角色**：Definition / Provider / Consumer；缺 Provider 时 Consumer 无意义
3. **包依赖 + 版本**：`peerDependencies`、目标 `dsh` 版本、目标 Profile 表面（`web` / `headless`）

预览期官方明确会破坏兼容。社区目录已经把「静态检查 ≠ 能跑 ≠ 安全」写成原则。评价体系必须把 **兼容证据** 当成一等公民，不能只做五星。评价绑定到 `插件版本 + DSH 基线 + 环境`。

### 0.4 视觉系统约束（若未来嵌进官方 Web UI）

官方 Web 客户端：`--dsw-*` token、CSS Modules、禁止 Tailwind / 组件库。本规划按 **独立工坊站** 设计，token 命名预留可映射到 `--dsw-alias-*`。

## 1. 产品定位（只谈界面）

**一句话**  
给 DeepSeek Harness 做一座浏览器里的创意工坊：用封面和标准化元数据选插件，用一键把 Bundle 挂进当前 Profile，用标签网和依赖图代替翻 GitHub。

**不是**  
设置页插件列表、文档站、npm 搜索页、又一个 awesome README。

**主场景**  
用户已经在跑 `dsh web`（或即将跑）。打开工坊，3 次点击内完成「看懂 → 信得过 → 装进当前档案」。

**三个角色**

| 角色 | 要完成的事 | 界面重心 |
|---|---|---|
| 使用者 | 找、看、装、卸、组预设 | 货架、快览、一键、我的档案 |
| 作者 | 让物品被正确理解、被评、被依赖 | 标准化卡片、兼容徽章、依赖声明 |
| 策展人 | 做合集 / 预设档案 | 合集编辑、依赖闭合检查 |

## 2. 五条原则如何变成界面规则

这五条是 [02](02-product-scope.md) 非 UI 定义的界面投影。

### P1 一键式极简

对应后台：`InstallIntent → Resolve → Explain → Confirm → Apply → Verify → Commit/Rollback`。

- 卡片上只暴露一个主按钮：**安装** / **已安装** / **更新**。
- 默认装进 **当前 Profile**（顶栏始终可见，可切换，不可隐式换档）。
- 需要信任（Git `prepare` / `allowBuilds`）或需要必填 Config 时，**不离开列表**：快览里一次确认。
- 禁止把用户推到「复制 `dsh plugin add ...`」作为主路径。命令只作为次要「复制安装命令」。
- 装完不跳详情。按钮就地变成已安装，并给出「配置 / 在依赖图中查看」弱入口。
- 危险权限、生命周期脚本、来源变化、冲突单独升级，不把这些塞进同一颗无说明按钮。

### P2 视觉主导 + 信息标准化

每张卡同一骨架，禁止作者自定义卡布局。  
封面表达「这是什么种类」，文字只承载不可从图读出的字段。  
字段集合由工坊规定，作者填空，不发明新槽位。README 只能补充，不能代替规格表。

### P3 社区驱动的动态评价

评分不是唯一信号。并列展示且可筛选：

- 星级（用过的人，绑定版本与环境）
- 安装量（当前 Profile 挂载数，不是 GitHub star）
- **兼容证据**：针对某 `dsh` 版本的加载 / 工具调用实测
- 最近 7 天评价（防老插件霸榜）
- 问题标签：崩、权限过大、和某插件冲突

安全信号与大众评分分离：deny / yank / advisory 不能被好评抵消。

### P4 精准标签 + 网状检索

标签是图，不是云。三类正交轴：

- **形态**（工具 / 钩子 / UI / 适配器 / Skill / 合集…）
- **能力键**（`inject` 与提供的 `ctx` 键）
- **表面**（web / headless / 任意）

点任一标签 = 以该节点为中心展开邻居，而不是追加一条 AND 过滤就结束。

### P5 依赖与合集直观化

- 缺依赖时主按钮不能假装可装，要变成「安装此件及依赖」。
- 合集 = 有序列表的 Bundle 集合，对应 `dsh.profile.bundles` 的一段；可安装发布是不可变 lock。
- 图里节点是 Bundle，边是 inject / seam / 显式 `requires`。
- 「被最多其他物品需要」做成首页货架，对标 Steam 的 Most Required。

## 3. 信息架构

```
工坊
├── 首页 Home                 发现（货架）
├── 浏览 Browse
│     ├── 插件 Items
│     ├── 合集 Collections
│     ├── 作者 Authors
│     └── 已保存检索 Saved Queries
├── 物品快览 Quick View       列表上下文 overlay（不是独立路由）
├── 物品页 Item
├── 合集页 Collection
├── 作者页 Author
├── 我的档案 My Profile
│     ├── 已安装
│     ├── 更新
│     ├── 合集草稿
│     └── 档案切换 / 对比
├── 检索结果 Search
└── 关于 / 安全说明 About
```

本地导航固定为：`首页 / 浏览▾ / 我的档案▾ / 关于`。  
顶栏右侧：**当前 Profile 芯片** + 搜索 + 已装数量。

路由建议（仅前端）：

| 路由 | 页面 |
|---|---|
| `/` | 首页 |
| `/browse/items` | 插件目录 |
| `/browse/collections` | 合集目录 |
| `/item/:id` | 物品页 |
| `/collection/:id` | 合集页 |
| `/author/:id` | 作者页 |
| `/me` | 当前档案 |
| `/search` | 检索（可与 browse 共用壳） |

快览不占路由，用 `?qv=:id` 保持可分享、可左右切。

## 4. 页面规划

### 4.1 首页 — 发现货架

对标 Steam 工坊 Home：宽屏货架 + 中部紧凑列表，不把全部插件一次性铺成墙。

**区块（可配置顺序，默认如下）**

1. **Hero**  
   一句话：把 Bundle 挂进你的 Profile。右侧是当前档案摘要（已装数、待更新、最近一次兼容扫描、Companion 连接态）。

2. **本周热门**  
   大卡横向货架。排序 = 近 7 天评分，不是历史安装量。防基础设施插件永久占坑。只计入带当前大版本证据的评价。

3. **按形态逛**  
   形态芯片墙：工具、UI、钩子、适配器、Skill、记忆、工作流、合集。每项带计数。

4. **按能力键逛**  
   `tools` / `llm` / `agents` / `sessions` / `sandbox` / `subagents` … 点开进入以该键为中心的网状检索。

5. **Tab 精排列表**（紧凑横条，提高密度）  
   `最热门` / `最多安装` / `最近更新` / `最新发布`  
   副标题写清窗口，例如「过去三个月评分」。

6. **被最多其他物品需要**  
   对标 Steam Most Required。展示的是 **Service Definition / 框架型 Bundle**。副标题固定文案：「其他插件要正常工作，通常先要有这些」。

7. **官方 / 核心层**  
   `@deepseek-ai/dsh-base`、`dsh-web-app` 等 inbox bundle。只读，标「随 Harness 提供」，没有安装按钮。

8. **你关注的作者 / 当前档案缺的依赖**  
   有数据才出现。缺依赖货架是工坊相对 Steam 的加分项。

### 4.2 浏览页 — 目录

左栏持久筛选 + 右栏 4 列大卡（窄屏 2 / 1）。筛选改条件时列表就地更新，不整页刷新。

**左栏分组（顺序固定）**

| 组 | 控件 | 说明 |
|---|---|---|
| 特殊 | 仅看已装 / 仅看可更新 / 排除与当前档案冲突 | 对标 Steam Special Filters |
| 形态 | 多选 | 工具、钩子、UI… |
| 表面 | 三态 | 只要 web / 排除非 web / 不限 |
| 能力键 | 三态 +/− | 提供该键 / 依赖该键 / 忽略 |
| 兼容 | `Exclude incompatible` | 默认排除对当前 dsh 版本失败的项 |
| 信任 | npm / GitHub / 本地 / 已审计 | Git 源默认降权展示 |
| 日期 | 发布 / 更新窗口 | |
| 评价 | 最低星、最低兼容次数 | |

顶栏：`Browsing: 插件` + `N entries matching filters` + 排序。  
排序项必须带解释 tooltip：`最热门（一周评分）` ≠ `最多安装`。

已选条件变成可删芯片。提供 **保存此检索**，写入浏览下拉的 Saved Queries。

### 4.3 快览 Quick View — 主决策面

悬停卡片右下角出放大镜；点击不离开列表。这是 P1 的主战场。

**左**  
封面 / 截图条（UI 插件强制；纯工具插件用「能力示意」标准化插图，禁止空白）。

**右，字段顺序锁定**

1. 名称、形态徽章、兼容灯
2. 作者
3. 元数据表：版本、目标 dsh、体积、安装数、收藏、最近实测日期
4. 提供的 `ctx` 键 / 需要的 `inject`（小图）
5. 截断描述（作者 280 字短描述，不是 README）
6. `需要以下物品` 缩略图行，溢出 `+N`

**底栏（从左到右，不可重排）**

- 主按钮：安装 / 安装及依赖 / 允许构建并安装 / 已安装 / 更新
- 次按钮：配置（仅已装且有 Config schema）
- 收藏、加入合集、复制命令
- 赞 / 踩
- 右侧：奖励式小章（可选，后期）

面板外左右箭头：同一结果列表上下项。Esc 关闭。

**信任插层（仍在快览内）**  
Git 源或需 `allowBuilds` 时，主按钮先展开 3 条：

1. 将执行该包的 `prepare`（安装期跑作者代码，不在 agent 沙箱内）
2. 建议钉 commit
3. 确认允许构建

没有「我已阅读」长文。三条 + 确认。这对应 ADR-008：一键是事务，不是零确认。

**Config 插层**  
仅当 schema 有 `required` 且无默认值时拦截安装。其余字段装后再配。

### 4.4 物品页 — 深读，不承担主转化

快览负责装。物品页负责信任与图。

模块顺序：

1. 标题条 + 主按钮（与快览同一状态机）
2. 媒体（截图 / 短视频 / 能力示意）
3. 标准化规格表（见第 6 节）
4. 依赖图（本物品为中心，一度邻居默认展开）
5. 「谁依赖我」
6. 评价与兼容报告
7. 版本与变更
8. README / 长描述（折叠，默认只露前屏）
9. 讨论（二期）

### 4.5 合集页

合集是 **有序 Bundle 列表**，不是标签。可安装的 collection release 固定成员、版本、digest、层序和目标环境。

- 封面 + 策展说明
- 闭合状态：可独立安装 / 缺 N 个依赖 / 与当前档案冲突 M 项
- 主按钮：**安装合集**（按 lock 中的 bundle 顺序写入 Profile）
- 列表每行：序号、卡、已装态、本行冲突
- 允许「追加到当前档案」或「覆盖为新档案」（两个明确选项，默认追加）
- 导出为可分享的 bundle 清单视图（只展示，不实现发布协议）

### 4.6 我的档案

这是 Steam「已订阅」+ 客户端 Workshop 页的合并，展示的是本机事实，不是云端愿望单。

- 档案切换器（`web` / `headless` / 用户自建）
- Companion 连接态；未连接时列表只读
- 已装列表：可拖拽排序（映射 `dsh.profile.bundles` 顺序，后层覆盖前层，UI 必须用文案说清）
- 每行：启用/停用（对应 patch `disabled`）、更新、移除、打开配置
- 冲突与缺口：红灯条目置顶
- 与某合集 diff：「合集有、你没有 / 你有、合集没有」
- 空态：引导去本周热门，而不是空白表

### 4.7 检索

搜索默认 **名称 + 短描述 + 能力键 + 作者**。齿轮里才切「仅名称」。  
结果页与浏览页同壳。无结果时给出：改标签、看合集、看「被需要」货架。

## 5. 一键交互状态机（P1 的完整规格）

界面状态是 [05](05-install-lifecycle.md) 事务模型的投影，不是另一套安装语义。

```
空闲
  ├─ 可装 ──────────────────► 安装中 → 成功 → 已安装
  ├─ 缺依赖 ───────────────► 确认依赖清单 → 安装及依赖 → …
  ├─ 需信任 ───────────────► 信任插层 → 允许构建并安装 → …
  ├─ 需必填配置 ───────────► Config 插层 → 安装 → …
  ├─ 已安装 ───────────────► 已安装（主按钮静默）
  │                            次级：配置 / 移除 / 查看图
  ├─ 可更新 ───────────────► 更新
  ├─ 冲突 ─────────────────► 主按钮禁用，改出「查看冲突」
  └─ 不兼容当前 dsh ───────► 主按钮禁用，改出「仍要装」（降级、二次确认）
```

规则：

- 任何一步失败，按钮回到可重试，错误用一行人话 + 「复制命令」兜底。
- 安装中不可重复点；列表里该卡骨架屏脉冲。
- 成功只用按钮变色 + 档案计数 +1，不做全屏庆祝。
- 移除是次级，藏在 `…` 或已安装下拉，需一次确认。
- 未连接 Companion：主按钮变为「复制安装命令」，不假装已写入本机。

## 6. 标准化信息架构（P2）

字段必须来自结构化清单与解析结果，见 [04](04-domain-model.md) 与 `spec/workshop-manifest.schema.json`。声明与 artifact 冲突时，界面以 artifact 为准并出示告警。

### 6.1 卡片骨架（所有形态共用）

```
┌─────────────────────────┐
│ 封面 / 标准化示意        │  3:2
│                    [🔍] │  悬停：放大镜 + 主操作
├─────────────────────────┤
│ ★★★★☆  兼容●  形态      │
│ 标题（最多 2 行）         │
│ By 作者                  │
│ 提供 tools · 需 llm      │  一行键芯片，最多 3 +N
└─────────────────────────┘
```

禁止出现在默认卡上的东西：README、star 数、许可证全文、长 tag 云、安装命令。

### 6.2 形态 → 默认封面语言

作者可换图，但不能换结构。无图时用工坊统一示意，避免「工具插件全是空白」。

| 形态 | 示意语言 |
|---|---|
| 工具 | 单色工具剪影 + 一个 `ctx` 键名 |
| 钩子 / 策略 | 瀑布/闸门图形 |
| Web UI | 真实截图（强制，无图降权） |
| LLM 适配器 | 模型插头 |
| Skill | 书页 / 指令条 |
| 合集 | 叠卡 |
| 基建 / Provider | 层/积木 |
| 官方 inbox | 锁定标记 |

### 6.3 规格表（物品页 / 快览共用同一键集）

| 键 | 显示名 | 来源（设计假定，不实现） |
|---|---|---|
| kind | 形态 | 清单枚举 |
| role | 角色 | Definition / Provider / Consumer / Bundle |
| version | 版本 | semver |
| targetDsh | 目标 dsh | 范围 |
| surfaces | 表面 | web / headless |
| provides | 提供 | ctx 键 |
| injects | 需要 | inject[] |
| requires | 硬依赖物品 | bundle id[] |
| configRequired | 安装前必填 | schema.required |
| trust | 分发通道 | npm / github / local |
| license | 许可 | SPDX |
| lastProven | 最近实测 | 日期 + dsh 版本 |
| installCount | 安装 | 工坊侧统计 |

作者不能增删键，只能留空。空键显示「—」，不藏行。

### 6.4 文案音量

- 短描述：280 字，快览只用这个。
- 长描述：物品页折叠。
- 按钮动词固定：安装、安装及依赖、允许构建并安装、更新、已安装、查看冲突。
- 不用「订阅」—— dsh 的动作是挂载，不是 Steam 订阅。若要品牌感，可用「挂载」，但主按钮仍用「安装」。
- 不用「安全认证」包装静态扫描或星级。

## 7. 社区评价体系 UI（P3）

### 7.1 信号分层（必须同时看见）

```
[ ★ 4.6  128 ]   [ 安装 3.1k ]   [ 兼容 12/14 · 0.1.0-rc.5 ]   [ 7 日 ↑ ]
```

四段不可合并成一个分数。兼容段用灯色：绿（当前版本通过）、黄（仅旧版本通过）、红（当前失败）、灰（无实测）。灯色必须伴随文字。

### 7.2 评价表单（极短）

装过才能评。表单 4 控：

1. 星（1–5）
2. 本次用于哪个 dsh 版本（预填当前）
3. 三个可选标签：能用 / 易冲突 / 权限吓人
4. 140 字

无长评编辑器。长讨论去讨论区（二期）。作者/协作者评价单独标记，不进入普通分母。

### 7.3 兼容报告卡（独立于星级）

每条报告一行：`dsh 版本 · 加载成功/失败 · 工具调用成功/失败 · 日期 · 来源（社区/作者/雷达）`  
列表可按「只看当前版本」滤。  
首页「本周热门」只用带当前大版本证据的评价。

### 7.4 反霸榜

- 默认货架用 7 日窗口
- 「最多安装」与「最热门」拆开并解释
- 官方 inbox 不进热门竞逐
- 无封面的 UI 插件、无 `dsh.bundle` 声明的库，目录默认降权或打「不可一键安装」

## 8. 标签与网状检索（P4）

### 8.1 三轴标签，禁止混成一朵云

| 轴 | 例子 | 点选语义 |
|---|---|---|
| 形态 | `tool` `hook` `ui` `adapter` `skill` `collection` | 这是什么 |
| 能力 | `provides:tools` `injects:llm` | 图上的边 |
| 表面 / 渠道 | `surface:web` `trust:npm` | 约束 |

自由标签可用于发现候选，进入标准筛选前需映射到受控词汇。

### 8.2 网状而不是折线过滤

浏览页在应用 AND 过滤的同时，提供 **「以当前焦点展开」**：

- 点 `injects:tools` → 右侧出现邻居抽屉：提供 `tools` 的 Definition、同键的其他 Consumer、常用合集
- 点某物品的能力芯片 → 把该物品设为图心，筛选器同步
- 面包屑是路径：`tools → Consumer → 视觉`，可回退任一节点

这是相对 Steam 标签栏的增强：Steam 的 tag 是属性，dsh 的 `inject` 是边。

### 8.3 检索语法（齿轮里展示，不作为主 UI）

对标 Steam 搜索齿轮。支持：

- 默认：标题 + 短描述 + 键 + 作者
- `kind:ui` `provides:tools` `injects:llm` `surface:web`
- `-trust:github`
- `requires:dsh-memory`

保存检索 = 保存这组轴，不是保存关键词字符串 alone。

## 9. 依赖与合集可视化（P5）

### 9.1 三种图，不要一张万能网

| 图 | 用在 | 节点 | 边 |
|---|---|---|---|
| 安装闭合图 | 快览 / 安装确认 | 将被写入 Profile 的 Bundle | 硬依赖 |
| Seam 图 | 物品页 | Definition / Provider / Consumer | 角色关系 |
| 档案层图 | 我的档案 | 已装 Bundle，按列表顺序自上而下 | 覆盖 / 冲突 |

默认一度邻居。超过 12 个节点改用清单 + 「展开图」。  
缺的节点用虚线框 + 一键补齐。  
冲突用红边，悬停说明「后层整行覆盖 `id: foo`」。

### 9.2 合集 = 可安装的有序闭包

合集编辑（作者/策展）：

- 从已装或搜索加入
- 拖拽顺序（即 bundle 层序）
- 实时显示闭包是否完整
- 不允许加入「不可一键安装」的纯库包，除非标为「开发依赖、不挂载」

合集浏览卡与插件卡同骨架，形态徽章为「合集」，封面上叠 3 张子封面。

### 9.3 「被需要」货架规则

进入该货架的物品需满足：被 ≥ N 个其他已索引物品声明为 `requires` 或作为唯一 Provider 提供某高频 `ctx` 键。  
文案避免「最受欢迎」，只用「最常被需要」。

## 10. 视觉系统（独立站，可映射官方 token）

### 10.1 气质

不要复制 Steam 蓝图纸，也不要做成文档站灰底。  
Harness 是「可拆的运行时」，视觉用 **深色工作台 + 层/补丁** 隐喻：卡片像可插拔模块，档案页像层叠板。  
「STEAM 创意工坊」只描述交互范式。项目不使用 Valve/Steam 的商标、素材或页面设计。

### 10.2 Token（设计名 → 以后可对 `--dsw-alias-*`）

| 角色 | 用途 |
|---|---|
| `bg-canvas` | 页面底 |
| `bg-panel` | 卡、快览、左栏 |
| `bg-elevated` | 下拉、对话框 |
| `line` | 1px 分割 |
| `text-primary / dull` | 标题 / 次级 |
| `accent` | 链接、芯片选中 |
| `ok` | 安装主按钮、兼容绿 |
| `warn` | 信任、Git 构建 |
| `danger` | 冲突、失败 |
| `star` | 评价 |

圆角小、阴影弱、网格紧。主按钮实心 `ok`，次按钮描边。  
字体：界面无衬线；键名、版本、命令用等宽。

### 10.3 密度

- 桌面浏览：每行 4 卡（≥1440 为 5）
- 首页货架：大卡；Tab 精排：横条
- 快览：两栏，最小宽度 960
- 移动：单栏卡，快览改底部 sheet，主按钮粘底

### 10.4 动效

- 筛选：列表交叉淡入，150ms
- 快览：200ms 缩放+遮罩
- 安装成功：按钮色变，无撒花
- `prefers-reduced-motion`：切瞬间

### 10.5 若嵌入官方 Web UI

遵守上游 `docs/web-styling.md`：CSS Modules、只用语义 token、焦点可见、不在功能组件里写死颜色。工坊作为独立路由或独立站均可，组件不要引入 Tailwind。精确前端技术栈仍暂缓，见 [10](10-decisions.md)。

## 15. 设计验收（界面自己能验的）

1. 未读文档的人能在快览里完成一次「安装及依赖」，中途不进物品页。
2. 任意两张卡字段位置一致，形态只改示意与徽章。
3. 「最热门」与「最多安装」在 UI 上能读出差别。
4. 点能力芯片能看到邻居，而不是只少一批卡。
5. 合集安装前能看见层序和缺口。
6. Git 源不能比 npm 源少一次确认。
7. 未连接 Companion 时整站仍可逛，只是主按钮降级。
8. 窄屏快览主按钮不丢。

## 16. 和 Steam 工坊的映射（设计备忘）

| Steam | 本工坊 | 有意不同 |
|---|---|---|
| 订阅 | 安装到当前 Profile | 动词是挂载，有层序 |
| 物品 | Bundle（不是任意 git 仓库） | 无 `dsh.bundle` 则不能一键 |
| 合集 | 有序 Bundle 列表 / 不可变 release | 层序 = 覆盖顺序 |
| Most Required | 被最多 `requires` / 唯一 Provider | 按依赖图，不按 star |
| Quick View | 同结构 | 增加信任插层与 inject 图 |
| DLC 三态 | 能力键 + 表面 + 兼容 | 筛的是运行时图 |
| 保存检索 | 同 | 保存的是三轴，不只是关键词 |
| Create Collection 入口 | 我的档案里「从已装创建」 | 避免 Steam 全量后入口丢失 |
