# 官方 UI 抓取、对齐与工具化计划

> 抓取对象：`https://www.deepseek.com/harness/`（中文）与 `/harness/en/`（英文），以及页面内嵌的官方 Web UI 截图。  
> 对照对象：上游 `packages/client/ui-theme`（`--dsw-*`）与 [11 UI 设计规划](11-ui-design-plan.md)。  
> 目的：工坊站在视觉上站进官方产品家族；把官网上「产品化 / 展示化」的区块改成可操作工具，而不是再做一版宣传页。  
> 抓取日期：2026-08-14。

相关文档：[01 上游基线](01-deepseek-harness-baseline.md) · [11 UI 规划](11-ui-design-plan.md) · [10 决策](10-decisions.md)

## 1. 抓到了什么

官方不是一块 UI，是 **两套表面共用一个品牌核**：

| 表面 | 地址 / 出处 | 角色 |
|---|---|---|
| 营销站 | `deepseek.com/harness/` | 讲故事、导安装、导文档、导 GitHub topic |
| 产品 Web UI | `npx @deepseek-ai/dsh web`，官网页用真截图展示 | 设置插件、对话、轨迹、Agent 预设 |

营销站把产品截图嵌进叙事。工坊要对齐的是 **产品工作台**，营销站只借品牌核与信息架构，不复制整页宣传节奏。

### 1.1 营销站信息架构（按出现顺序）

1. 顶栏：鲸标 `Harness` · 中/EN · GitHub · 开发者文档 · **社区插件**
2. Hero：`DeepSeek Harness 开发者预览版` / `一切皆插件` + 三按钮（查看 GitHub / 开发者文档 / 社区插件）
3. 一键使用 / 源码安装：可复制的 `npx @deepseek-ai/dsh web` 与 `git clone …`
4. `Agent = Model + Harness`：模型是灵魂，Harness 让 Agent 在真实场景持续工作
5. 三块机制：Cordis 内核 · 插件提供能力 · 配置层自由组合
6. 设计思路：一切皆插件 · 每一次运行都有迹可循（配 Trajectory 真截图）
7. 四种运行模式卡：标准 / PTC / 极简 / 创造
8. 自定义你的 DeepSeek Harness：再给一次 npx / clone
9. 加入 DSH 插件生态 + 微信公众号
10. 页脚：MIT · 公司版权 · 安全使用政策 · 数据处理说明

「社区插件」官方链到 `https://github.com/topics/dsh-plugin`，不是市场。这是工坊要补上的洞。

### 1.2 产品 Web UI（来自官网截图，不是推断）

**设置 → 插件**

- 深色工作台，左侧设置导航：通用设置 / 模型 / **插件** / Agent 预设
- 右上「打开配置文件」
- Tab：插件配置 | 插件列表
- 搜索「搜索插件」
- 计数：「插件列表 132」
- 两列圆角卡：插件 id + 绿点「已启用」或暗色「已停用」+ 下拉
- 展示的是 **本机已挂载的 Cordis 行**（include、timer、hmr、llm、session…），不是社区目录

**轨迹（Trajectory）**

- 顶栏会话标题 + 模式芯片「标准模式」
- 对话 | **轨迹** 双视图
- 时间轴：Input / Model / Tools 三色泳道
- 事件流标签：SYSTEM / USER / CONTEXT / ASSISTANT / TOOL，颜色编码
- 右侧检查器：Summary / Payload / Result / Schema / Timing
- 底栏：任务进度 + 「给智能体发消息」

这是官方对「运行有迹可循」的产品化。工坊不该再做成第二张 Trajectory 海报，而要把 **插件对运行时的贡献** 做成同样可点的检查器。

### 1.4 产品客户端 token（`--dsw-*`）

来源：`packages/client/ui-theme/src/styles/design-platform.css`。

- 静态色板：`deepseek-450` ≈ `rgb(86,134,254)`，贴近营销蓝；另有 green / amber / red / bluish-neutral
- 语义：`--dsw-alias-bg-base`、`bg-layer-*`、`state-success-primary` = green-500 `rgb(34,197,94)`
- 产品主按钮在暗色主题下接近 **浅色填充 / 近黑文字**，不是大面积品牌蓝铺底
- 规则（`docs/web-styling.md`）：**CSS Modules + `clsx`，禁止组件库和 Tailwind**；功能组件只用 `--dsw-alias-*`，不写死色值

截图里的「已启用」绿点对应 `state-success`，不是营销蓝。

### 1.5 官方在展示、但没有做成工具的东西

| 官网上的展示 | 用户实际能做的 | 缺口 |
|---|---|---|
| 「社区插件」导航 | 跳进 GitHub topic 列表 | 无封面、无兼容、无一键挂载 |
| 四种运行模式卡 | 读说明 | 不能选一个模式装进 Profile |
| 插件设置截图 | 只能本地打开设置页翻 132 个 id | 无发现、无依赖、无评价 |
| Trajectory 截图 | 本地会话里才能用 | 工坊侧看不到插件会往日志写什么 |
| 复制 `npx` / `git clone` | 粘贴终端 | 不是「把这个 Bundle 写入当前档案」 |
| 创造模式文案 | 「检查运行时、试验插件、创作 preset」 | 没有面向社区的 preset/合集编辑器 |
| Cordis 三块机制图 | 叙事 | 没有可点的 seam / inject 图 |

## 2. 对齐原则（修订 11 的视觉立场）

[11](11-ui-design-plan.md) 写过「不要复制 Steam 蓝图纸，用深色工作台」。抓取后补三条硬约束：

1. **品牌核跟官方，工作台跟 `dsh web`，营销节奏不跟。**  
   工坊是工具站。Hero 可以短，但不能做成第二份 `everything is a plugin` 长页。

2. **两套 token 分层，不混用。**  
   - 外站壳（顶栏、页脚、文档感页面）：可映射 `--ds-*`（品牌蓝、Host Grotesk 标题）。  
   - 工具表面（卡片网格、快览、档案、图）：映射 `--dsw-alias-*`（层、成功绿、告警琥珀、错误红）。  
   实现时仍遵守「功能组件不写死色值」。若嵌进官方 Web，只留 `--dsw-alias-*`。

3. **不使用 Valve/Steam 视觉，也不使用第三方「马头鲸橙 `#F25C0C`」。**  
   官方核是鲸 + `#4D6BFE`。橙色属于无关仿作，禁止进入本项目。

4. **文案跟官方词表。**  
   已启用 / 已停用 / 插件列表 / Agent 预设 / 标准模式 / 轨迹 / 给智能体发消息。主按钮仍用「安装」，不用「订阅」。

5. **商标边界。**  
   可「看起来像同一产品家族」，不可复制官方鲸标作工坊 Logo；可用中性「层/插件」标记 + 文字 `DSH Workshop`。

## 3. 展示 → 工具：改造清单

这是本计划的产品核心：官网上每个展示块，对应工坊里一个可完成任务的工具。

### T1 社区插件导航 → 目录工具

- **现在**：外链 GitHub topic。  
- **改成**：工坊自己的 Browse。顶栏保留「社区插件」四字，落到 `/browse/items`。  
- **工具能力**：分面、三态能力键、兼容灯、保存检索。  
- **验收**：从官网同名入口进来的人，30 秒内能按「UI / 需要 tools / 排除不兼容」缩小列表，而不掉进 GitHub。

### T2 一键复制命令 → 挂载工具

- **现在**：复制 `npx` / `git clone`。工坊可保留为次要「复制命令」。  
- **改成**：主路径是「安装到当前 Profile」。未连 Companion 才退回复制。  
- **工具能力**：11 的安装状态机 + 信任插层。  
- **验收**：已连接时主按钮从不把用户送去终端。

### T3 四种模式卡 → Preset / Profile 安装器

- **现在**：标准 / PTC / 极简 / 创造是说明卡。  
- **改成**：四种官方模式映射为 **只读系统合集/预设**（inbox，随 Harness 提供）。点击「用于当前档案」打开闭合图：将启用哪些 bundle、将停用哪些。  
- **创造模式** 变成入口：跳到合集编辑器，「从当前档案另存为预设」。  
- **验收**：用户能比较四模式的 bundle 差集，而不是只读四段文案。

### T4 设置页插件列表 → 我的档案层叠板

- **现在**：本地 132 个 id 的启用开关。  
- **改成**：同一视觉语言（两列圆角卡、绿点已启用、搜索、计数），但每张卡多出：形态、兼容、来源、依赖缺口、更新。可拖层序。  
- **「打开配置文件」** 保留为高级入口，不是主路径。  
- **验收**：档案页一眼能从「132 个内部 id」里认出哪些是社区 Bundle。

### T5 Trajectory 海报 → 插件检查器

- **现在**：官网用轨迹图证明「有迹可循」。  
- **改成**：快览/物品页右侧检查器，Tab 对齐官方：`Summary / 贡献 / 依赖 / 兼容 / Timing(版本史)`。  
  - Summary：短描述 + 形态 + 表面  
  - 贡献：注册了哪些 tool / section / slot（对标官方 Payload）  
  - 依赖：inject / requires（对标层级）  
  - 兼容：版本矩阵（对标 Result）  
- **不做** 会话回放。那是 runtime 的轨迹，不是市场的职责。  
- **验收**：用户不进 README 也能回答「装了它，模型会多看到什么」。

### T6 Cordis 三块机制图 → 可点 Seam 图

- **现在**：内核 / 能力 / 配置 是静态叙事。  
- **改成**：物品页 Seam 图。点 Definition 看有哪些 Provider/Consumer；点缺口虚线框一键补齐。  
- **验收**：11 的「点能力芯片看到邻居」在此落地。

### T7 「加入生态」+ 微信二维码 → 作者/策展工具入口

- **现在**：口号 + 公众号。  
- **改成**：页脚保留官方链接；工坊侧提供「提交清单」「从已装创建合集」。不自建公众号墙。

### T8 Hero 长叙事 → 工作台首页货架

- **现在**：大标题讲架构。  
- **改成**：短 Hero（一句话 + 当前档案芯片 + Companion 态）+ 本周热门 + 被需要 + 模式预设条。架构故事链到「关于」。

## 4. 视觉对齐规格（供下一轮高保真）

### 4.1 壳层（像官网，但更短）

- 顶栏：左文字标、中导航（首页 / 浏览 / 我的档案 / 关于）、右 Profile 芯片 + 中/EN + 搜索  
- 背景：工具页用产品暗色（`dsw` layer），关于/文档可用营销浅底  
- 主 CTA：深色实心或浅色实心（跟产品主按钮），品牌蓝用于链接、焦点、选中芯片，不用于整页铺底  
- 命令块：等宽 + 复制，仅次级

### 4.2 工具层（像设置/轨迹，而不是营销卡）

- 卡片半径用 panel（16）而不是营销 card（24），更接近插件列表  
- 已装/已启用 = 成功绿点 + 文字，照抄设置页语义  
- 快览 = 轨迹检查器的市场版：左媒体、右字段、底操作、外左右切  
- 时间/模式类信息用等宽小标签，类似 SYSTEM/USER/TOOL 色点，但标签集换成形态/表面/信任

### 4.3 修订 11 的 token 表

| 11 原名 | 对齐后 | 官方依据 |
|---|---|---|
| `accent` | `brand` `#4D6BFE` / `dsw-static-deepseek-450` | 营销 + 产品色板 |
| `ok` | `state-success` green-500 | 已启用 |
| `warn` | amber-500 | 信任 / Git 构建 |
| `danger` | red-500 | 冲突 / 失败 |
| `bg-canvas` | `dsw-alias-bg-base` 暗层 | 产品工作台 |
| `bg-panel` | `bg-layer-2/3` | 设置卡 |
| 大标题字体 | Host Grotesk（外站） | 营销 |
| 工具内字体 | 跟 `dsw` 正文字族，不引入 Tailwind | 产品规则 |

11 第 10.1 节「深色工作台 + 层/补丁」保留。补丁隐喻继续用于档案层图，颜色改走官方中性层，不再自造一套灰蓝。

## 6. 实施阶段（仍只做设计与静态原型）

工程后端不在本计划范围。UI 工作插入 11 的 A–D，并增加对齐闸门。

### Phase 0 — 对齐闸门（本周）

- 冻结品牌核：蓝、绿、层灰、禁止橙、禁止 Steam 材质  
- 出一页「官方对照」：设置列表 vs 档案卡、轨迹检查器 vs 快览  
- 修订 11 组件清单：PluginCard 增加启用点；QuickView 改为 Inspector tabs

### Phase 1 — 工具化线框

优先画能替代官网展示的四块：

1. Browse（T1）  
2. 安装主按钮 + 信任插层（T2）  
3. 四模式预设条（T3）  
4. 档案层叠板（T4）

### Phase 2 — 检查器与图（T5/T6）

快览 Tab + Seam 图。没有这两块，工坊仍像「更好看的 GitHub topic」。

### Phase 3 — 高保真

暗色工作台、官方色板、1440/768/390。营销浅底只用于关于页。

### Phase 4 — 静态原型

假数据走通：从「社区插件」进 Browse → 快览检查器 → 安装态 → 档案列表出现绿点。不接 `dsh plugin`。

## 7. 明确不做

- 不复制官网整页（大段架构文案、微信二维码墙、双份 clone 区块）  
- 不实现 Trajectory 会话回放  
- 不把四种模式重新发明成工坊私有 runtime；只映射官方 preset/bundle 组合  
- 不在功能 UI 引入 Tailwind（与上游产品规范冲突）。营销壳若用 utility，必须隔离，不得泄漏进卡片/快览  
- 不使用官方鲸标作工坊标识  
- 不把 GitHub star 或官网截图包装成「官方认证」

---

## 8. 验收

1. 把工坊截图和 `dsh web` 设置页并排，非设计师能看出同一产品家族（层、圆角、绿点、暗底）。  
2. 品牌蓝只作强调，主按钮和已启用态不靠大面积蓝。  
3. 「社区插件」留在站内，不再把主流量送进 topic。  
4. 四种模式可比较、可应用到档案，而不是四张说明卡。  
5. 快览能回答「装了会多什么能力」，而不只是好看封面。  
6. 未连 Companion 时仍可逛，主按钮降级复制——官网的命令块降为兜底，不再是主路径。

## 9. 建议的下一张设计稿顺序（取代 11 §17 的纯 Steam 序）

1. 官方对照板（设置列表 / 轨迹检查器 / 营销顶栏）  
2. PluginCard + 启用点 + PrimaryInstallButton  
3. QuickView Inspector（Summary / 贡献 / 依赖 / 兼容）  
4. 四模式预设条  
5. 档案层叠板（对齐设置→插件）  
6. Browse + 首页短 Hero  

先 1–3，对齐才算成立；再铺发现货架。
